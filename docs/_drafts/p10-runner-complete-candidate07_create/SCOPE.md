## Original normal semantics and failure boundaries

Duplicate v2 ID replaces the train while preserving the `_trains` mapping
object and any external reference to the old train. Direct constructor color
is not stringified; v2/legacy color is. Negative unit produces zero car length
and unscaled speed; zero unit is also unscaled. Positive unit scales speed even
when base speed is zero or negative. Empty path versus one-point path must not
be merged. New cars use the original `_Car` defaults and mutable list identity
contract; legacy attach uses the original `s0 - chain_back(j)` rule with the
new train's chain length. No synthetic helper result is sufficient evidence
that the returned train is in the real engine mapping and subsequent full
FrameResult/Effect output uses it.

ROOT fixed the following two semantics before implementation:

1. Original legacy publishes a fresh train/dirty flag before parsing points;
   a later conversion error retains that partial publication. A new explicit
   partial-create native report publishes that fresh train/dirty side effect
   before the same ordinary conversion exception is re-raised. Foreign
   conversion compatibility uses the original entry once, in its original
   observable order. Native budget/overflow/allocation rejection retains the
   old correct mapping/output and never runs a large Python fallback. A finite
   normal successful input is prepared completely before publication.
2. Python `int(car_count)` is unbounded and v2 only stores it, without creating
   cars. The proposed ABI retains that original integer as host metadata and
   returns a native negative/nonnegative normalization selector (negative
   chooses the original zero clamp), rather than
   silently truncating it to a C integer. A nonempty legacy attach with a count
   beyond the actual owner allocation budget is explicitly rejected; v2 and
   the direct constructor need not allocate cars just to store a large count.

Foreign supplier/class/ABI/source refusal retains the explicitly qualified
original compatible entry once. Budget refusal, MemoryError, overflow,
cancelled preparation and invalid adoption never invoke a large old tick or
geometry fallback. No broad exception handler turns these into success.
