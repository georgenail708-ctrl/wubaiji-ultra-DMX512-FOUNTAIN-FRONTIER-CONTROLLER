Actual adaptation uses normalized **base-256 magnitude bytes**, with a separate sign, rather than the candidate's proposed30-bit digits or CPython's private live PyLong representation. `ce_trajectory_integer_bytes.inc` parses immutable signed little-endian two's-complement inputs into owned magnitude scratch, and writes owned signed-byte results. `ce_trajectory_integer_arithmetic.inc` preserves the sign/magnitude add/subtract and borrow/carry order of `x_add`/`x_sub` using uint8 digits and unsigned/int temporaries. `ce_trajectory_integer_float.inc` retains the top53 significant bits plus the guard/sticky bits, rounds ties to even, and uses `ldexp` only after exact subtraction and rounding. It reports integer-to-float overflow, and reconstructs finite integral doubles with the `frexp`/binary-digit principle of `PyLong_FromDouble`. Python object allocation/refcounts/error indicators become explicit C scratch ownership, caller-owned result byte pools and semantic reports. No private PyLong layout, Python.h, Python callbacks or GIL-dependent C API is used.

The sample kernel performs exact int/int subtraction before float multiplication and converts the base separately at the original addition point. Mixed int/float operands convert in the original right-minus-left order. Endpoint/non-numeric selectors preserve original objects and do not perform integer-to-double conversion. Original first-inclusive segment order and left tie are retained. C `source`, `sample`, `applier`, `add`, `merge`, `values`, `integer_subtract`, `integer_conversions` and `semantic_errors` counters come from completed kernel actions or successfully computed semantic errors; metadata serialization does not increment them.

Existing project `_ce_mod_div`, double `_ce_round_half_even` and `ce_layer_sparse_write` are reused at their compatible stages. Range endpoint values are rounded/clamped before interpolation; final range integer results remain unclamped. Ordered cross-clip addition applies upper saturation after each event and preserves negative values, which subsequently receive the original uint8 conversion error. Sparse merge validates a whole universe before writing its copied base and commits universes in the original order. No original showfile, registry, cache/record source, clock0–30, fixed test/oracle or central CE registration file is changed by this domain implementation.

The exact upstream source ranges, Git blob identities and primary read evidence remain in `k05z-exact-integer-native-plan01.md` and `k05z-batched-abi-plan01.md`. This records source implementation; root's actual build/test/Main/packaging receipts determine validation and delivery status.
